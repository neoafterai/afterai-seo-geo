# AfterAI SEO/GEO — 使用说明 / Usage

版本 0.2.2（公开试用版）。**一个 skill，四步完成：评估 → 计划 → 实施 → 复评维护。** 其他 Markdown 是助手按需读取的参考资料，你不需要逐份学习或填写。

## 开始使用

复制整个 `afterai-seo-geo/` 文件夹到支持本地技能的 AI 工具的技能目录，保留子目录。具体安装位置以宿主配置为准；新对话中检查能否发现 `afterai-seo-geo`。也可让能读取本地文件的助手直接读取 SKILL.md 及引用文件；不保证所有 AI 产品自动识别。

打开客户自己的文件夹，直接说：

> 使用 AfterAI SEO/GEO，开始优化 example.com。我们用中文交流，网站面向澳洲英文用户。先评估和给计划。

之后常用的只有三句话：

| 你说 | 助手做什么 |
|---|---|
| 开始优化 / start | 了解必要资料，从评估开始，不自动改站 |
| 继续 / continue | 读取进度，完成当前授权范围内的下一步 |
| 本月检查 / monthly check | 对比上次记录，给本月结果和修改建议 |

想单独做一件事也可以直接说，例如“只检查首页”“给英文客户报告”。“继续”不会把只评估扩大成改站；已批准工作会连续推进，不需要每一步回复继续。

English example: “Use AfterAI SEO/GEO to assess example.com for Australian English customers. Give me an audit and a plan first.” English conversation gets English responses; website and report languages are separately respected.

## 可以评估哪些网站

**线上和本地都支持**，实际读取取决于宿主能力。给网址就读取在线网页；给本地目录／HTML 就读取文件，能运行本地预览时再检查实际页面。没有浏览器或无法启动时，先完成源码可验证部分，其他项目标未测，不要求先上线。首次宽范围评估会问你选**全站检查**还是**代表页面抽样**；你已指定范围时不再问。

某个读取工具出现 403 或超时，先看其他获准工具是否仍能读取公开内容；这只说明该工具受阻，不能直接断言网站挡住了搜索爬虫。只有取得原始 HTML／DOM／响应证据，才判定 title、meta description、canonical、JSON-LD 等原始字段；网页读取器显示的标题不等于已检查 `<title>`。

- 线上：“评估 https://example.com，先不要修改。”
- 本地：“评估当前文件夹的网站，尚未上线。先读源码，能运行预览就检查页面。”
- 本地已启动：“评估 http://localhost:3000，网站面向澳洲英文用户。”

报告明确写“线上评估”“本地预览评估”或“仅源码评估”。本地可检查内容、代码及实际可运行的布局和功能；真实收录、排名、流量和 AI 推荐要有线上证据，不能由本地代码推算。网上网页的文字抓取也不等于已验证手机布局。

## Guided workflow

每轮通常只问 1–3 个影响当前步骤的问题，但完整访谈可以分多轮继续，直到影响目标词和页面选择的关键决定得到回答；没有固定题数，已有资料不重复问。助手填写和维护记录，你只需补业务事实、审阅具体方案、完成需要人工进行的操作。中文沟通且网站受众未说明时，先问网站仅英文、英中双语还是其他语言；已说明则不再问。

首次完整 SEO/GEO 优化把访谈分成两段，不把30个问题一口气交给客户。**检查前**问全站还是抽样，并简要确认最重要的业务结果、客户原始关键词（没有指定词也记录）、目标市场和网站语言；暂时答不出的目标词不妨碍可独立完成的只读评估与初步评分。**首次报告完成后**，若业务、重点服务或关键词仍未确认，先交付评分、已证实的问题与缺测，再问最重要的业务及转化、客户指定关键词（没有可委托助手扩展）、目标市场与语言；依赖这些答案的内容、页面增删和 GEO 建议暂不定稿。若客户继续计划或改站，结合报告追问过去网站最大的问题、已做过哪些 SEO/GEO 或网站改动及结果、希望未来网站让顾客完成什么、哪些页面／视觉／品牌／业务规则必须保留；再按需要追问 GSC 线索、目标客户和冲突事实。请客户明确选择首要与次要词组及对应页面，或委托助手根据证据选择，然后给出正式优先级和分阶段修改计划。已答过的不重问，不知道旧问题可以答“没有已知历史”。只要报告时，访谈问题是可选的后续入口；窄范围技术修复只问与该修复有关的决定。

开始首次宽范围检查时，若你没有指定范围，助手会问：“你希望检查全站，还是先抽查有代表性的页面？”全站指盘点约定范围内可发现的独立页面并分批逐页检查；页面多就报告进度与未查项，不把部分完成说成全站完成。抽样会先列样本、页面类型和排除范围。两种方式都按实际证据评分并显示覆盖率；[页面范围规则](references/audit-scoring.md#页面范围)解释重复 URL、筛选页和读取限制的处理。

完整项目的实际依赖顺序是：**简短开场与检查范围 → 只读评估及报告 → 报告后访谈与方向 → 核对网站关键事实 → SEO 基础及内容 → GEO 增强与实测 → 按需要建设知识库**。这仍属于四步流程，不增设新阶段。事实核对由助手盘点约定范围内的页面和模板，把已核实、冲突、未测分开；你只决定无法从可信资料确认的业务事实，不必逐页审稿。事实问题未解决时，可先做只读 SEO 技术检查和独立修复，但不能把不确定内容写成确定声明。知识库不是每个网站必做，也不必等建好才能开始 GEO。

| 步骤 | 助手完成 | 怎样进入下一步 |
|---|---|---|
| 1 评估 | 简要了解目标、关键词、市场和语言，让你选择全站或抽样；盘点本轮页面事实及冲突，检查适用的 SEO、GEO 和视觉项目，交付分数、覆盖与缺测 | 先给报告；没有 GSC／后台也可完成能验证的部分，缺项写明 |
| 2 计划 | 报告后询问旧问题、已有改动和希望的网站状态，复用已知答案；扩关键词、映射页面，制定 SEO 及后续 GEO 计划，记录事实冲突、改前基线及可选知识库条件 | 客户明确选择或委托决定优先词／页面方向，并确认涉及本批的正确事实、业务规则及修改范围 |
| 3 实施 | 助手在批准范围内批量检查并按需修复适用 SEO 项；验收所需基础后再做依赖的 GEO 工作；每批核对事实、目标语言、手机桌面和功能，新疑点只暂停依赖它的页面 | 验收通过后按已有授权发布；没权限则给人工操作步骤，不冒充已修改 |
| 4 复评维护 | 区分预览／上线结果，按同口径复评，观察真实效果，给下月清单 | 需要新修改时确认其具体范围；月检可手动触发，定时需实际设置 |

平时只显示“已完成什么、下一步、需要你补充什么”，详细评分、证据和任务表保存在记录中，需要时展开。所有适用 SEO 设置由助手按类别与页面组检查；给用户看重要问题、修改范围、数量、代表性改法和待确认例外，逐页或逐配置的改前／改后证据留在记录中。已有明确的本地修改授权时，不逐页索要批准。只有必要事实、范围或发布决策才停下来讨论；不要为每张表单和每项已授权操作重复确认。

如果你已授权本地改动，并确认或委托了相关业务与关键词决定，助手在记录具体方案后应继续完成实际编辑和验证；呈现方案不是再次索要同一许可。只评估／只做计划则到交付物为止。结构或品牌方向出现实质变化、Shopify 共享数据写入、上线范围超出既有授权时，单独给出具体改动供决定。

报告或对话提到网页标记时，按实际对象说话：类型、属性等属于 **Schema**；页面脚本、语法及其中的值属于 **JSON-LD**。两者都相关就都写，例如“活动页 JSON-LD 使用了不合适的 `Event` Schema”；首次出现时简要解释，不用“活动机器”或含糊的“机器可读资料”。未核实页面格式前不预设一定是 JSON-LD。网页正文可否被搜索与 AI 读取是另一项检查。

跳到后续阶段时，助手先补该动作必要的前置条件：例如直接“执行 GEO”却没有目标页和方案，就先做相关检查与具体计划。缺 GSC、真实用户性能或 AI 基线记为缺测，可继续其他有依据工作；目标身份、业务事实和授权不明只阻止依赖它们的动作。狭窄请求不强制跑完整流程。

SEO 相关基础验收后即可做 GEO，不用等 SEO 满分或排名上升。视觉检查贯穿评估和每批修改，保留原设计，重大改版单独讨论。发布前审阅具体改动；已有授权覆盖本次发布则不重复问。

先区分**新站首次上线**与**已有线上网站**。新站可以把开发工作分成几批，但首次上线前应完成约定首发范围内所有已知且能完成的核心页面、内容与答案、SEO 设置、适用的 GEO 和 Schema／JSON-LD、导航／内链、主要操作路径及手机桌面验收；不要把已确定的核心改动留待上线后才决定。上线后再核对实际访问、抓取与索引配置，观察 GSC、真实查询和 AI 回答，并根据证据改进。尚无素材或事实时明确调整首发范围或解决缺口，不把核心缺口称为“已准备好”。知识库和非核心扩展按需安排，不要求首发前做全。

已有线上网站才默认分批发布：**先完成最重要的一批 → 验收并按授权上线 → 核对线上结果 → 再做下一批**。SEO/GEO 共用修改可同批完成，不用等所有未来优化结束或排名上涨才发布。每阶段说明改什么、需要什么资料、如何验收与恢复，并记录上线版本。没有发布权限就标待上线，不把本地完成当线上完成。

## Worked example

**以下是虚构的已上线网站操作示例，不是已执行的客户案例。** 假设一家悉尼本地服务商的网站已上线且有英文页面，操作者用中文沟通，宿主能读写本地项目并访问网站。网址 `https://example.com` 仅为占位；表中的发现和授权均为演示，不能用于真实报告或其他客户。

| 进度 | 用户输入／助手动作 | 应交付的简短结果 |
|---|---|---|
| 开始 | 用户：“开始优化这个网站，用中文交流，网站只面向澳洲英文用户。先评估和给计划。” | 助手问首要目标、已有重点词，并让用户选全站或代表页面抽样；市场与网站语言已给出，不重复问。若用户选抽样，先列首页、核心服务页、常见问题页、联系页等实际样本及排除范围，再只读检查。此时不改站。 |
| 评估 | 假设实际检查发现服务页的询价链接失效，导航只写笼统的 `Services`，页面已有 title／description，但正文未清楚说明服务与咨询步骤；客户尚未确认服务区域，没有 GSC 或真实 AI 回答。 | 先交本轮报告、初步评分和覆盖率，说明“已确认问题：询价链接失效；站内机会：服务页顺序与导航不清楚；缺少资料：服务区域”。不在本示例编造分数，不把抽样叫全站检查。 |
| 报告后访谈与目标词确认 | 准备计划或首次修改时，助手指向报告中的询价路径问题，问客户过去是否遇到询价流失或做过哪些改动、希望新网站怎样引导咨询，以及哪些品牌／业务要求要保留；已回答的首要目标不重问。客户说明没有预先指定关键词，要求提出候选供选择。 | 将旧问题、已做工作、目标网站要求及词组决定写入档案；客户选定首要和次要词组，或明确委托助手选择。普通的“开始修改”不能替代未决事实与方向。助手批量核对已有标题和描述，不为凑词强改。 |
| 第一阶段计划 | 客户选择主词及页面方向后，核对已存在的 title／description，适合目标意图则保留；用现有已核实内容把服务页调整为“服务是什么 → 适合谁 → 怎么咨询”的阅读顺序，把笼统导航改为已确认服务类别的英文名称，并修正询价链接。服务区域未确认前不写相关承诺；列目标文件／位置、原值、新值、预览和恢复方法，保存改前基线。 | “第一批修好咨询路径并让核心服务更容易找到、看懂。第二批有真实资料后补深入回答与案例；独立需求才考虑新页。知识库暂缓。”客户确认主词／页面方向、涉及本批的规则和改动范围；计划本身不代表已获修改授权。 |
| 修改与预览 | 用户批准上述具体本地修改；助手调整服务页现有内容顺序、导航标签和询价链接，核验目标、手机桌面布局及无提交的联系路径。 | “本地已验证，待上线。”保留按钮已有的英文文案，例如 `Enquire about this service`；不因中文交流新增中文页面。没有浏览器则视觉仍未测，先交付人工验收步骤。 |
| 上线 | 用户审阅具体差异后：“把刚才验收的这一批发布到已确认的正式网站，仅限这次服务页顺序、导航标签和询价链接修改。” | 有发布能力才执行，并按上线清单核验；没有能力则给人工发布步骤，保持待发布。发布后若检查受阻，注明实际发布事实和缺测，不能说验收通过。 |
| 第二阶段 | 第一批线上验收通过，客户提供获准使用的真实案例及确认的服务区域。助手据此补充具体回答与案例；若某项独立服务需求无法由现有页清楚承载，则提出新页面、导航入口和内链方案，用户批准后实施并按发布范围上线。 | 中文解释“改哪里、为什么”，英文网站回答实际问题；不虚构客户评价，不保证 AI 引用。未提供资料只暂停依赖该资料的内容。 |
| 复评维护 | 用户：“本月检查。”助手在既有范围内读取记录、同口径复查和实际可取得的数据。 | 分开报告已修复问题、准备度变化及真实搜索／AI 观察；无真实数据则保持未测，列下月任务，不默认已经创建自动月检。 |

已授权的工作会连续推进，表格不是要求每行都回复“继续”。只查首页时就缩减为首页范围；只有网址、没有代码权限时，具体修改转为人工操作单。第一次实测可在现有进度记录中简记重复提问、最费人工的一步、无法执行的建议和无用报告内容，用于之后简化，无需新增问卷。

**如果同一类网站尚未上线：**在客户确认首发目标和页面范围后，助手会先把上例中已知的服务页内容、导航、询价路径、适合的标题／描述、内链及适用的 SEO/GEO 检查合在首发前完成和预览验证。真实案例或服务区域未经证实就不写；若它们决定核心页面能否准确成立，先解决事实或与客户明确调整首发范围。首次上线后才判断真实抓取、收录、查询表现和 AI 回答，再规划有依据的扩展。

## 没有工具时怎么做

无需安装 Python、Node、其他 skill 或付费 SEO API。联网、浏览器、文件编辑和 Shopify 权限由宿主提供；不可用时，助手继续能验证的部分，把其余交付为人工步骤。既有 AI 产品和网站环境费用不属于本项目免费承诺。

人工步骤每次说明实际位置、要做什么、可复制的目标语言内容、预期结果及需回传的证据。实际结果核验后再记完成，不把建议当执行。

完整 GEO 观察默认 10 个问题×3 个界面（ChatGPT 搜索、Google AI Overview、Gemini），约 30 次查询；单语用目标语言，英中双语各 5 题。可以分批完成，未测留在原问题组，不删除以美化指标。只评估技术／内容时不要求先完成这 30 次查询。Google Search 观察默认人工，其他采集须符合平台允许条件。没有实际回答就不报真实 AI 推荐结果。

每月例行检查可以固定抽查原问题组中 2–4 题，并在相同界面、市场和语言下比较；若没有可比旧记录就建立新基线。报告必须写明抽样范围，不能把小样本当作全组表现。正式完整复评、重大改版或异常排查仍可重测完整问题组。Shopify 店铺可按需评估官方 Knowledge Base 和 Catalog 商品入口，但二者都不保证 AI 推荐；安装应用或调整渠道设置另按实际影响决定。

## 数据和继续工作

### Record storage

记录在每个客户自己的 `seo-geo/` 中，助手按需创建：`profile.md`（资料）、`plan.md`（任务）、`progress.md`（进度）、`reports/`（报告）、`evidence/`（私有证据）。不要求你手工创建空模板；无文件写入能力时可在对话中交付记录供你保存。

客户资料不放入公开 skill 仓库。首次写入前检查实际目录、Git 跟踪／忽略状态，以及静态资源、构建复制和部署发布范围；Git 忽略不等于不会被网站发布，已经跟踪的文件也不会因添加忽略规则自动变私有。不要将记录写入 public、static、dist 等实际会公开的目录，或会整体发布的站点根目录。

若默认位置可能公开，使用同一客户工作区内已核实不会部署的私有记录目录，并记录实际根路径；该实际根路径替代模板中的 `seo-geo/` 前缀，根目录内仍为 `profile.md`、`progress.md` 等，不重复嵌套 `seo-geo/`。无法确定私有位置时先在对话交付，不写敏感记录，不擅自修改部署配置。恢复时沿用已记录位置，找不到就确认路径，不创建另一套互相冲突的记录。未经授权不上传客户材料。

记录 ID 与跨次引用规则见 [执行记录模板](templates/execution-log.md)。在同一客户文件夹的新对话说“继续”即可核对进度恢复；客户身份冲突先解决。没有旧记录的首次月检只建立当前基线，不编造上月结果。

评分是项目诊断，不是排名公式。缺测会影响覆盖率，不能用已检查项目高分冒充全站高分。真实关键词及 AI 推荐／引用另列，不保证第一。Shopify 未发布主题不能隔离共享产品数据；写入按实际影响处理。

## 可选的精确指令

默认报告按 [报告模板](templates/audit-report.md) 先给有证据的评分和覆盖率，再给已证实的问题、缺测和可以独立判断的技术优先项。若业务或关键词方向尚未确认，报告末尾先提问，页面内容与结构改动及分阶段路线待回答后定稿；不把网站现状猜成客户的战略选择。技术计算放私有附录；重大故障和主要缺测仍在正文说明。已有真实 AI 回答或你要求对比时，可分析竞争者被引用的页面；没有实际回答就不假装做过引用分析。

想直接指定阶段，可说：全面评估 / audit、扩展关键词 / keywords、页面规划 / map pages、SEO计划 / plan seo、GEO计划 / plan geo、执行SEO / run seo、执行GEO / run geo、视觉检查 / design check、GEO测试 / test geo、重新评分 / rescore、本地商家检查 / local audit、Shopify修改 / Shopify changes、查看进度 / status、继续优化 / resume、客户报告 / client report、使用帮助 / help。自然语言也可以，不必记语法。
