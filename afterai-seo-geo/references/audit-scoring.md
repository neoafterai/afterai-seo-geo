# Audit and scoring

量表版本：`0.1.2`。本项目诊断量表，不是 Google 或 AI 平台排名公式。按实际检查证据评分，不以措辞积极程度、内容字数或已花工作量评分。

## Input reading modes

支持两种入口：线上网站 URL 和本地网站。先识别输入，不要求本地项目先部署或提供公网域名。记录评估环境：`live`（线上）、`local-preview`（本地已运行）、`source-only`（仅文件）。用户同时提供网址和代码时分别记录版本与结果，不默认二者一致。

| 输入 | 如何读取 | 可取得的证据与限制 |
|---|---|---|
| 线上 URL | 用实际可用的网页读取工具取得页面正文／HTML；需要时检查 HTTP 响应、robots、sitemap，并用浏览器查看渲染页面 | 可检查在线内容、可访问性和渲染；阅读工具若只返回摘要／转换文本，不据此断言原始标签或响应头。索引／流量另用 GSC 等证据，AI 推荐另测 |
| 本地 HTML、源码或构建目录 | 在用户指定项目内读取项目说明、路由、页面、模板、元数据和相关配置；静态站读取 HTML，框架站区分源组件与构建输出 | 可核验文件中明确存在的内容、链接目标、标记及配置；动态模板输出、响应、交互、布局及线上配置不能仅凭源码确认 |
| 已运行本地网页，例如 localhost | 用可访问该地址的浏览器和读取工具检查实际响应、渲染 DOM、手机桌面和主要路径；同时关联本地版本 | 可验证本地运行和视觉表现；不证明部署后的响应、CDN、索引或搜索结果。宿主浏览器可能不能访问用户电脑的 localhost，失败则如实降级 |

本地读取顺序：确认项目根目录和相关文件 → 检查现有说明与已运行预览 → 如需运行，先查看项目声明的启动命令及副作用，再在可用环境启动现有本地预览 → 核验可访问地址后检查。只读评估不授权修改源码、安装依赖、运行迁移、连生产数据或部署；启动条件不足时保留源码评估并给必要操作说明。静态文件可直接查看；涉及相对资源、路由或脚本时，`file://` 的表现不能代替 HTTP 预览。不要上传本地项目到第三方来代替本地读取，也不要读取无关目录或凭据。

评分沿用同一量表，但证据按环境分开：本地能完整验证的条件可计入**本地准备度**，仅在源码中推测的运行效果不得通过；要求公开 URL／线上部署证据的条件仍未测。开发环境有意设置的 noindex、鉴权或 localhost 地址不当成线上故障；生产配置未知也不标通过。S08 仍要求真实用户数据，实验室或本地加载速度只作诊断。实际收录、搜索排名、流量和 AI 推荐在仅本地环境下记未测，不扣成零分、不冒充真实排名。

没有部署域名时 canonical／sitemap 中的生产地址可列待配置，不自行用 localhost 替代正式地址。首次部署后建立线上基线，不能把本地与线上混合成同口径涨分。

## 页面范围

读取档案，确认目标域名、市场、语言、业务类型、关键转化和权限。发现页面来源记录为 sitemap、导航、源码路由或客户清单。公共抓取、渲染页面、GSC 索引状态分别记录；能打开网页不证明已被搜索索引。

页面少则逐页检查。页面多时按类型和语言选代表样本：主页、关键服务／产品／集合、联系／预约、主要内容及每种语言至少一个对应页面；补充已知流量页和问题页。记录已发现 URL 数、检查 URL 数和未覆盖类型；无法知道全站规模则写未知，不声称全站穷尽。

开始读取前，用一句话说明本轮目标、环境、页面清单或数量上限，以及暂不覆盖的范围。用户指定范围优先；未指定时由助手按网站规模提出有限样本并开始只读检查，不增加必需的确认步骤。选择能覆盖关键类型和语言的最小实用样本，不把固定页数当完整评估标准。跟随链接也受本轮上限约束；避免追踪参数、筛选组合和重复 URL 无限扩展，确有独立内容的版本另作判断。

清单完成或达到上限即汇总；遇到登录、限流或能力限制时保留失败证据并继续其余可检查项，不反复尝试同一障碍。新发现的页面和需深入的问题放入后续待办，说明扩展理由；已观察到的严重故障必须立即披露，不因不在样本内而隐藏。调整本轮范围时明确说明并记录，新范围不能悄悄混入已冻结基线。有限样本完成只称“本轮检查完成”，不能称全站无问题；评分仍按实际适用项与缺测计算。

初评可先做探索检查。关键词和问题集确认后，在修改前固定正式样本、指标条件、量表版本、类型模块和权重。原始证据写 `evidence/<run-id>/observations.md`，使用 E001 等唯一 ID，记录 URL、时间、方法、观察和限制。截图是视觉证据；没有浏览器不根据 HTML 猜外观。

初评交付条件：在结束本轮评估前，按本轮明确样本和暂定页面角色整理逐项证据，输出三个维度的初步分数、覆盖率及缺测。关键词／业务优先级未确认只影响依赖这些资料的条件，不能推迟全部计分。“台账未填写”是待完成工作，不是缺测理由。确无完整验证项时按 V=0 规则显示未测。正式基线随后确认；样本或口径变化不能直接宣传涨分。

正文按 [报告模板](../templates/audit-report.md) 先评分，再列最重要／其次／可以稍后；完整逐项表和计算放附录或私有详情文件，不直接当经营者正文。

每个已检查的样本页分别读取实际 `title`、主要标题、`meta description`（含缺失或空值）和适用的 JSON-LD；记录页面 URL／文件、读取方式与版本。S04、S05 和 G10 的判定须对应本页证据，不得用另一页的描述或通用套话充当逐页验证。若只能读到搜索摘要而非页面源码／渲染 DOM，就不能据此断言元标签或结构化数据通过。发现字段与可见事实冲突时，即使某项因另一条件缺证据而未测，也要在正文显式列出已知错误。

初评不能只查上述元数据。对约定范围内适用的抓取／索引、URL 规范化、sitemap、重定向、内链、正文、图片、语言版本、手机体验、性能、Schema／JSON-LD 及行业信息，用 [SEO 检查清单](seo-implementation.md#seo-coverage-checklist) 记录已查、问题、不适用和未测；评分仍按本文件量表，不另造分数。跨页业务事实先盘点并标核实、冲突或未测；客户未确认的事实不因网页上重复出现就视为正确。

## 计分方法

每个检查项分成下表 A、B 两个可观测条件。已观察全部条件：满足两个为 1、仅一个为 0.5、都不满足为 0。任一条件缺证据则该检查项未检查，不猜半分。不适用要给业务或页面理由；缺权限、抓取失败不是不适用。

条件级不适用必须在逐项表记录理由：只剩一个适用条件时，整项保留原权重，该条件通过得 1、不通过得 0、缺证据则整项未测；两个条件都不适用时才移除整项权重。不能把未知当不适用来取得满分。原量表 0.1.0 没有明确此规则，跨版本比较须用新口径复核旧证据或标不可比。

对页面级检查，基线选定 n 个适用页面，每页权重为该项权重/n，ID 用 `S01@page-id`；门店级同理。每页判断 A/B，缺测页保留其权重。站点级只记一次。这样只检查一个好页面不能代表所有样本。不同语言单列页面证据。

设 A=适用总权重，V=已检查权重，E=Σ(已检查项权重×0/0.5/1)。不适用从 A 移除；未检查留在 A，但不进入 V。

- 已检查项目得分 = 100×E/V。
- 检查覆盖率 = 100×V/A。
- 全范围可能区间 = [100×E/A, 100×(E+A−V)/A]，这是缺测边界，不是统计置信区间。
- V=0：得分“未测”；A>0 时覆盖 0%、区间 0–100。A=0：整项“不适用”，不出分。
- 完整覆盖时区间两端等于实际分数。覆盖不足时只能称“已检查项目得分”，不能称整站确定得分。

用完整精度计算，最后显示一位小数。复核：权重加总、0≤E≤V≤A、区间上界≤100、每个有效 ID 唯一。计算不一致就先修表再给分。可以使用宿主已有计算能力，但不得要求使用者安装脚本。

纯算术例：40 权重已通过、40 未检查、20 有理由不适用。A=80、V=40、E=40；已检查得分 100、覆盖 50%、可能区间 50–100。不能报告“网站 100 分”，也不能把未测 40 分说成不合格。这不是允许 SaaS 因无门店删除整个类型预算；应选择适用 Software 项后建立实际台账。

## 报告和复评

G09 的补充判定：即使已充分检索，没有可供比较的相关站外材料时，B 条件仍未测，整项未测；记录“缺乏佐证”，不能以未发现矛盾判通过，也不能擅自按失败给半分。本判定在量表 0.1.2 明确，旧版据此重算或标不可比。

证据使用运行内 E-ID，跨文件按 [执行记录](../templates/execution-log.md) 写成 run-id:E-ID，避免月检覆盖或混淆旧证据。

按 [audit-report.md](../templates/audit-report.md) 保存逐项表及计算过程，分别出三个分数。重大索引阻断、错误门店信息、坏的预约／购买入口置顶，不被高分掩盖。

GSC 数据按实际目标国家、页面、查询、设备、时间窗口记录。没有展示不能编造排名；GSC 平均排名不是固定地区地图排名。若当前属性可访问 [生成式 AI 表现报告](https://support.google.com/webmasters/answer/16984139)，单独记录其 Search AI Overviews／AI Mode 展示量、页面／国家／设备及时间口径；该报告与普通 Web 报告有数据包含关系，不能相加当总量，也不等于 ChatGPT／Gemini 的推荐次数或“第一名”。报告不可见时记录属性、访问权及可能的数据不足限制，标未测，不能写零曝光。专门报告界面显示 `~` 或 `-` 的不可用值导出后可能变成 0，核对原界面再解释，不把这类 0 当实测零展示。另只读核查 [Google 生成式 AI 控制项](https://support.google.com/webmasters/answer/16908024) 的纳入／排除／继承状态；显示“继承”时追溯最近已配置的父属性，无法读取则有效纳入状态未测，不能默认纳入。变更该设置须说明影响并取得针对该设置的授权。

### GSC input checks

首次读取或收到新导出时，先核对以下信息，记录在原证据中，不另建必填表：

- **属于哪个网站：**GSC 属性及范围（Domain 或 URL-prefix）、对应客户／域名、文件或连接来源和取得日期。不能靠文件名猜客户；属性覆盖范围不等于本次分析目标范围。
- **采用什么口径：**数据时间窗口、搜索类型、国家、设备，以及查询／页面等筛选条件和聚合维度；未提供的筛选信息写未知，不默认“全部”。
- **是否完整：**列是否缺失、是否只导出部分行／选定页面、是否有截断或完整性未知。部分查询行不能冒充全站总量；不把页面表与查询表相加造成重复统计。
- **能否使用或比较：**错客户／错属性数据先隔离，不用于本客户结论；口径未知或不一致时不做趋势归因。可核实的局部记录仍可作局部参考，缺测不阻止其他工作。前后比较保留相同口径和范围；不能用缺失值代替零或直接平均不兼容汇总表中的比率／排名。

关键词规划、评分和月检共用这次核对结果；已有完整来源信息不重复询问客户。
