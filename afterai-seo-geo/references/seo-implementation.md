# SEO implementation and visual verification

输入为已确认的档案、正式基线和计划。只执行批准范围；修改后有差异及验收才更新完成状态。Shopify 写入另读 [shopify.md](shopify.md)，本地资料读 [industries.md](industries.md)。

## SEO coverage checklist

完整项目在约定的网站范围内先盘点相关页面、模板和站点配置，再逐类记录“已检查／问题／不适用及理由／未测”。评分量表是摘要，不能替代以下执行清单；也不表示必须改动每一项或穷尽无限 URL。按模板批量扫描，同类页面抽样核验实际输出，关键业务页逐页检查，说明覆盖数与未覆盖范围。

1. **业务事实先核对：**品牌与主体、实际产品／服务、服务和配送区域、联系方式及营业时间、价格／费用／优惠条件、资格与承诺、案例／评价、时效信息、预约或购买规则；把多页面、后台资料和客户原话的冲突列出，必要时请客户指定权威值。无法核实的事实标未确认，不能擅自改成看似一致。
2. **抓取与索引：**预期公开页面的响应、鉴权、robots.txt、meta robots、X-Robots-Tag、渲染可读性和可用的 GSC 索引证据；不要把可访问等同于已收录。
3. **网址与发现：**canonical、重复或参数 URL、重定向、404／断链、sitemap、导航及重要内链；多语言站检查语言版本与 hreflang 是否适用和正确。
4. **页面内容与搜索呈现：**已确认的页面意图、正文事实与完整性、title、meta description、H1／标题结构、锚文本，以及有意义图片的替代文字；逐页留存需保留／修改／未测及原因。搜索结果摘要可能改写，不把元描述当展示保证。
5. **体验与性能：**手机可用性、关键路径、实际渲染、图片和页面加载；Core Web Vitals 只有具备适当真实用户数据才判断通过，实验室数据只用于诊断。
6. **适用增强：**已有或确有用途的 Schema／JSON-LD 与可见事实、行业本地信息、Shopify 产品／集合／变体及可用性。没有适用场景不强加标记，也不为 SEO 制造新业务事实。

先处理关键事实错误、抓取／索引阻断和转化路径，再按确认的关键词与页面映射优化内容；其它独立技术检查可并行。SEO 基础完成并验收后开展依赖它的 GEO 内容与 AI 观察；知识库按 [规划中的判断条件](keyword-page-planning.md#phased-releases) 另行决定，不是必经阶段。

进入首批写入前，按 [决策访谈](../SKILL.md#decision-interview-before-implementation) 核对业务主目标、目标词与页面方向、本批正确事实和业务规则。已有访谈答案复用；窄范围技术修复只检查相关决定。例如“普通咨询是否必须填写活动日期”属于客户业务规则，不能仅凭现有表单或报告建议自行决定。新冲突只暂停依赖它的任务，列观察值请客户确认；其它独立且获准的任务继续。

准备修改 title、meta description、H1 或核心文案时，先读 [优先页面元数据决定表](../templates/optimization-plan.md#metadata-decision-for-priority-pages)：确认客户已明确选择或委托首要／次要词组，按已批准的页面组逐页对照现值、目标意图、可见内容和业务事实。助手自动生成候选文案；用户只需审阅本批方向、范围和少量代表性示例。已有明确本地修改授权时，按需批量修改确定性页面，保存每页改前／改后值和保留理由，不逐页索要确认；页面含未确认事实、承诺、语言或品牌语气时暂停该页并询问。未确认目标词时只做只读评估与草案，不把“开始执行修改”解读为关键词确认。独立且获准的技术、事实修复不因此停工。修改后核对渲染输出与目标语言，不能以标签存在或评分通过代替内容验收。

## 代码网站的工作批次

1. 检查当前项目规则、框架、路由、部署方式和现有未提交修改。不要覆盖用户工作或使用未知构建命令。
2. 从计划选择可执行依赖已满足的一小批任务，保存原值／差异及恢复方法。任务涉及线上共享数据先核对批准范围。
3. 使用目标网站语言修改内容与元数据，保持现有代码和设计规范。
4. 运行项目已有且适合改动的检查。没有测试环境时说明未验证什么，不输出“测试通过”。用本地或未发布预览核验页面。
5. 对照验收清单保存证据；失败项保留“已改未验证／受阻”，不发布。成功项为“已验证未上线”。展示具体改动及预览，已有明确上线批准覆盖本次批次时可继续；否则请求批准。
6. 发布后按 [上线验收短清单](#live-release-checklist) 核验实际结果，验收通过再记录“已上线”。不能把写代码当已部署。

## Live release checklist

每批发布后针对本次改动、受影响模板及关键入口检查，复用任务验收证据，不必全站重跑。保存实际线上 URL、时间、版本（可取得时）和每项结果；版本未知时不能猜发布版本。

1. **目的地与路径：**打开正式域名、变更页面和相关深层路径，核对预期状态／内容及实际重定向终点。涉及域名或重定向变更时检查相关 www／非 www、HTTP／HTTPS 入口，避免只验证首页。
2. **公开范围：**核对预定公开页是否残留测试用鉴权、意外 robots／noindex 或响应头限制；有意保密页面保留限制，不批量解除。
3. **地址信号：**按实际适用性核对 canonical、内链、sitemap 和语言对应地址，检查是否仍指向 localhost、预览域名或错误生产地址；不因清单强制新增原本不需要的标记或 sitemap。
4. **实际内容：**检查本批目标语言、业务事实、主要正文及适用结构化数据的线上输出。区分源 HTML 与浏览器渲染；只取得摘要不能证明原始标签正确。只确认“已保存”不能代替线上核验。
5. **显示与操作：**在手机和桌面核验本批布局及相关主要入口，例如咨询、预约、选变体或购买路径；遵守既有外部副作用授权，未获准不提交真实订单／咨询。未测环节单列。

只对有证据的项目标通过，其余为失败、未测或有理由的不适用。线上已变更但无法验收时，明确记“已发布、线上验收待完成”，在任务中保留受阻说明，不能说“未上线”或“验收通过”；依赖该验收的下一批发布暂停，其他独立工作可继续。发现关键故障先处理或按已有授权恢复。以上是发布验证，不证明已经收录或获得 AI 推荐。

## 修改顺序与判断

每批属于计划中的一个上线阶段。当前阶段验收通过后按授权发布并验证，再推进下一阶段；依赖未满足或上线失败时先解决，不等待所有后续优化做完。无发布能力如实保留待上线状态；获准继续的独立本地任务不冒充线上进展。阶段安排见 [分阶段计划](keyword-page-planning.md#phased-releases)。

| 顺序 | 检查与修复 | 注意 |
|---|---|---|
| 1 | 错误响应、意外 noindex／robots、鉴权、重定向循环 | 确认页面确实应公开，不撤销有意隐私或测试环境限制 |
| 2 | canonical、sitemap、重要导航及断链 | 保留预定索引结构；平台已有自动功能不重复添加 |
| 3 | title、主要标题、描述、正文意图及事实 | 准确自然，不以固定字符数／关键词密度机械评分 |
| 4 | 重要服务、产品、分类、文章及内链 | 优先改善已有页；新页需在批准的映射中 |
| 5 | 图片尺寸与加载、主要内容渲染、性能 | 保留作品质量，测量后定位瓶颈，不随意删除应用 |
| 6 | 对应语言页面、语言链接、适用 hreflang／canonical | 语言区域代码符合真实版本，不凭空生成翻译页 |
| 7 | 适用结构化数据 | 检查现有主题／应用输出，再修改；与可见事实一致 |

结构化数据生成的 JSON-LD 是被优化网站可能需要的代码，不是本技能包依赖。它必须按实际平台和当前官方规范验证，不能保证富结果或 AI 引用。FAQ 内容可以有用户价值，不以 FAQ 标记获得特殊展示作为默认理由。

发布顺序按依赖和影响排，不把“SEO 技术”与“GEO 技术”设成两个必须完全结束才能交接的批次：先确认并修正会误导顾客或搜索引擎的关键业务事实及访问／索引阻断；核对核心页的 title、主要标题、描述、canonical、内链和实际可读取内容；已有 Schema 的 JSON-LD 错误字段随对应可见事实同批修正并验证。再扩展独立的问题回答、案例或适用标记，并在发布后观察搜索与 AI 的实际表现。缺失 Schema 只有在内容真实、类型适用且有明确用途时才考虑新增；不能为了 GEO 把全部页面都加标记。独立的可执行工作可以同步准备。

只有公开访问权时输出：URL、位置、原问题、建议新内容、所需权限、验收及恢复建议。不得把建议标成已执行。

## 常见问题的执行分支

每次先判定 URL 应公开索引、仅可访问，还是应保密，再处理以下问题；把结果写进具体任务卡。

1. **抓取／索引冲突：**依次检查响应和登录限制、robots.txt、HTML robots 与 X-Robots-Tag，再看可得的 GSC URL 检查。robots.txt 的 Disallow 管抓取，不可靠地移除索引；爬虫被阻挡可能读不到 noindex。需要 noindex 生效时必须让爬虫读到它；私密内容保留鉴权，不能为了读 noindex 公开机密。只修正已确认非预期的限制，发布后重新检查，索引更新另待观察。
2. **重复 URL：**列实际重复版本、选择预定规范 URL，核对重定向、canonical、内链与 sitemap 是否一致。canonical 是信号，不是保证；没有显式标签不等于不能索引。依据重复风险决定方案，不能把所有分页、筛选和语言页都指向首页。sitemap 有助发现，不是每个站必须新增，也不保证收录。
3. **语言版本：**只有真实对应页面才配置 hreflang；核对完整 URL、有效语言／地区码、自己及相互返回引用。不同语言保留合理的各自 canonical，不把全部中文页规范到英文页。不因操作者中文沟通生成中文版本。
4. **页面下架或 URL 改名：**先检查流量、内链和替代内容；有对应替代再选合适的永久重定向，无替代时按实际下架需求处理 404／410，不把所有失效页跳首页。保存旧新映射并核查链接和 sitemap。

**内容与采集规则：**不用隐藏关键词、只给机器人看的操纵内容、批量低价值城市页、排名用途的链接交换／自动外链或伪造评论。AI 辅助写作仍要有真实事实和用户价值。检查可得 GSC 人工处置与安全问题记录；无权限列缺测。查询与平台测试采用允许的方式，不把能访问网站视作获准自动采集。

进入 GEO 的最低条件按任务判断：相关目标页身份、事实和语言明确；没有使该任务验收失效的未解决访问／正文读取／关键功能故障；依赖任务已经验证。其他 SEO 待办可继续保留，不要求满分、全部 SEO 做完或搜索排名已提升。原始 AI 基线缺失须披露，不能伪造来放行。

## 美观与功能贯穿批次

- 从现有截图提取品牌、字体、间距、图片比例和页面节奏。新增信息放在符合意图的位置，例如服务详情、作品说明、规格、简短问题回答；不把首页变成长篇关键词墙。
- 核验手机和桌面视口，记录具体尺寸；检查溢出、遮挡、文字层级、图片、菜单和主要动作。
- 核验链接、键盘操作和表单反馈。付款、发出真实咨询、预约占位、邮件通知等会产生外部效果的动作需要明确授权；优先测试环境或无提交验证。
- 如果文案变更造成严重拥挤，提出局部设计方案与范围，不自动整体改版。
- 无浏览器或截图只做可验证代码检查，视觉项写未测，提供人工清单。

## 免费工具与证据

使用宿主已有 fetch/search/browser，客户提供的 GSC 导出、可用的免费 PageSpeed 和结构化数据测试。工具不可用、免费额度不足、页面被登录拦截时保留具体失败及人工路径；不接付费服务补齐。

每条证据记录 URL／文件、日期、方法、实际观察、限制和任务 ID。动态平台规则如 schema 支持、爬虫、CMS API 在执行前核对官方文档；无法核对则标未验证，不套用过时片段。

规则复核依据：[noindex 与抓取](https://developers.google.com/search/docs/crawling-indexing/block-indexing)、[Spam policies](https://developers.google.com/search/docs/essentials/spam-policies)、[Sitemaps](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview)。执行时记录来源与核查日期；本项目任务顺序和评分不是官方认证。
