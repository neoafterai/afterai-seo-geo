# Shopify operations

这个文件是操作判断指南，不是 Shopify 连接器。先实际检查当前宿主可用的连接、读写范围及店铺身份。没有工具不虚构 API 调用，不要求付费应用。执行前核对 Shopify 当前官方文档、主题实际实现及权限；本包不硬编码 API 版本或后台菜单路径。

## 操作前

核对店铺域名、线上主题及工作主题 ID、商品／页面 ID 和语言市场。保存基线及原值。不把某个未发布主题的预览 URL 当成整个店铺独立沙盒。

| 对象 | 范围判断 | 预览／授权 | 恢复依据 |
|---|---|---|---|
| 主题文件、模板、主题内设置 | 确認选定主题，判断修改是否仅属于该主题 | 副本／未发布主题内验证，发布主题前确认 | 文件差异、原主题、修改前值 |
| 商品展示标题／描述；搜索列表 SEO title／meta description | 这些是不同字段，均按线上共享商品数据处理，除非工具证明隔离 | 指明实际目标字段、商品 ID、原值、新值和市场影响，具体批准后写入 | 各字段原值及目标 ID |
| 页面、博客、集合内容和 SEO 字段 | 可能直接影响发布内容及多个模板 | 先在本地提供文案／差异，核查发布状态，批准覆盖实际写入 | 原内容、状态及 URL |
| 翻译、市场和元字段 | 范围取决于所有者、语言和应用消费方式 | 检查实际引用，不假定未发布主题隔离 | 原值、语言、所有者和字段定义 |
| URL handle、重定向、导航 | 影响链接和可能的流量入口 | 映射旧新 URL、内链和恢复方案，单独说明影响 | 旧映射和引用列表 |
| 域名、结账、价格、库存等业务设置 | 不属于普通 SEO 内容修改 | 仅在用户明确要求且确认具体影响时实施 | 原设置及平台可用恢复路径 |

已明确批准某商品的具体新描述，且用户知道会影响线上共享数据时，不再重复询问同一写入。若只有“改未发布主题”的批准，不能由“顺手优化商品”推断已审阅具体共享字段；先呈现实际新旧值和影响。处理授权按具体变更而不是每次点击。

## SEO 检查

读取已存在的主题和应用输出，核对 sitemap、canonical、robots、标题、描述、产品／组织结构化数据及翻译处理。另核对目标商品／页面／博客的发布状态，以及适用的 `Unlisted` 状态和 `seo.hidden` 元字段：它们可能使页面从搜索和 sitemap 消失；先确认这是否是店铺有意选择，不能为提高分数自行改成公开。Shopify 已提供的功能先验证，不再生成冲突副本。不因追求评分重写 robots 或安装应用。

编辑主题用实际主题支持的语法和现有组件；修改产品／集合先确认事实、变体、地区和语言。批量优化搜索标题／描述时，区分商品展示名称／正文和 Search engine listing 的 SEO 字段，记录实际写入对象并核验渲染后的 `<title>` 与 meta description，避免误改顾客可见的商品名称。验证当前渲染结果，不能只看后台保存成功。无真实连接的模拟场景验证只证明指令判断，不证明该店铺可自动操作。

## 商品信息检查

按已有页面样本选择代表商品、关键变体和实际目标市场，不要求抓全店或读取某个固定 API。可用商品后台／导出、可见页面和结构化数据分别标明来源，访问不到就记未测。先确认实际业务，再按适用性检查：

| 检查 | 具体核对 | 形成什么任务 |
|---|---|---|
| 选择信息 | 尺寸及单位、材料、适用场景、必要限制是否足够且有依据 | 指向具体商品或相关说明页，提出需补字段及客户材料，不编造规格 |
| 变体 | 颜色、尺寸、型号等差异是否清楚，所选变体与可见价格／可售状态是否对应 | 记录商品和变体 ID、市场及观察时间；不擅自改价格或库存 |
| 履约与售后 | 实际配送范围、费用条件、取货、安装和退换说明是否易找到 | 链到适用政策或补说明；不把“未说明”推定为免费配送或支持退货 |
| 一致性 | 同一市场、币种和变体下的正文、确认商品资料与结构化数据是否一致 | 指出冲突字段及来源，先核实正确值，不默认后台、旧导出或页面某一方永远正确 |
| 影响范围 | 问题只出现在某商品，还是重复出现在同一模板的样本 | 写“检查 n 个，其中 m 个有问题”；模板原因须查文件或多页证据，未知全店规模不能外推 |

每个问题只需记录“商品 URL／ID及变体 → 字段 → 原值或缺项 → 依据 → 建议值／待提供 → 影响样本 → 阶段 T-ID → 验收”。优先放入现有阶段计划，维持原设计。遇缺事实只暂停该字段的文案，不阻止其他有依据工作。

复用 Commerce E01/E02、G02/G05 等既有评分项，不新增 Shopify 加分、不对同一检查义务重复计分。字段写入仍遵守共享线上数据授权；本节是检查清单，不是改价、改库存或业务政策的权限。

方法参考：[shopify-geo-audit](https://github.com/maxbuildog/skills/tree/main/skills/shopify-geo-audit) 的商品专项检查与样本范围表达；不依赖其扫描器，不将第三方缺陷比例当成本店数据。

## 没有连接或写权限时

给出可复制的 Markdown 操作单：店铺、对象 ID／URL、查找位置（按实际后台核对）、原值、建议值、是否即时上线、操作顺序、预览及验收、恢复步骤。明确“待用户实施”，等待实际回传证据后再验证。不要索要密码或把令牌存入客户报告。

## 验收

写入后发现内容错误或关键功能故障，先停止后续批次、保存当前状态及证据。原批准包含该对象的恢复操作且原值仍适用时可恢复并复验；否则展示具体恢复差异和影响再取得所需批准。不盲目重试写入或覆盖用户后续修改。

检查目标语言的线上／预览页面、必要源码或 DOM、手机与桌面、商品／联系路径。记录哪些环境已验证。主题发布与共享内容写入分开记录；后者可能已经上线，不要错误标记为待主题发布。
